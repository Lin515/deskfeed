# 快照协议 v1

DeskFeed 只消费一个端点，返回的是一份**完整**快照。所有字段要求如下；不符合的正文
**整份拒绝**，不会部分接纳。

最小例子：

```json
{
  "version": 1,
  "items": [
    {
      "id": "cpu",
      "label": "CPU",
      "value": "54℃",
      "state": "ok",
      "detail": "最近一次采样结果"
    }
  ]
}
```

## 顶层字段

| 字段 | 要求 |
| --- | --- |
| `version` | 必填。数值等于 `1` 才接纳；`1.0`、`1e0` 与 `1` 是同一个数值，同样接纳；字符串或布尔值不是数字，拒绝；其它数值拒绝。 |
| `items` | 必填数组，最多 64 项；允许空数组。 |
| `expiresAtMs` | 可选。非负安全整数，Unix 毫秒，取值 `0..9007199254740991`。**按数值判断，不按写法**：`1000`、`1000.0`、`1e3`、`9.007199254740991e15` 都合法（最后一个等于 `9007199254740991`）；`1e-3`、`1.5`、`9007199254740992`、负值、`null` 都拒绝。 |

## 条目字段

`items` 的每个元素必须是对象：

| 字段 | 要求 |
| --- | --- |
| `id` | 必填非空字符串，UTF-8 解码后不超过 128 字节；同一快照内唯一。 |
| `label` | 必填字符串，不超过 256 字节，单行，可为空。 |
| `value` | 必填字符串，不超过 1024 字节，单行，可为空。 |
| `state` | 可选字符串，只允许 `ok` / `warn` / `error`；省略即 `ok`。 |
| `detail` | 可选字符串，不超过 16384 字节，允许换行，用于详情展示。 |

- `label` 与 `value` **不能同时为空白**。
- 未知字段在各层都被忽略。
- 可选字段可以省略，但**不能用 `null` 代替**。
- 文本是纯文本，不是 HTML、Markdown、XAML 或格式化指令。业务单位直接写在文本里，
  例如 `54℃`、`12.30 USD`、`剩余 68%`。
- 一份合法的 `state: "error"` 是**业务状态**，不是结构错误，也不影响其它条目。

## 容量边界

| 项目 | 上限 |
| --- | ---: |
| JSON 正文 | 1 MiB（1048576 字节） |
| 条目数 | 64 |
| `id` | 128 字节 |
| `label` | 256 字节 |
| `value` | 1 KiB（1024 字节） |
| `detail` | 16 KiB（16384 字节） |
| JSON 嵌套深度 | 32 层 |

字符串上限按 **JSON 解码后字符串的 UTF-8 字节数**计算，不按 UTF-16 长度、字符数或转义写法
长度计算。超限整份拒绝，不静默截断成另一份快照。显示层的取舍不得改写协议内容。

这些常量只有一处定义：`src/core/snapshot.h`；`schema/snapshot-v1.schema.json` 与本文必须与它一致。

## 严格校验的细节

以下属于严格解析器的取舍（实现细则，见 `src/core/json.cpp`）：

- 正文必须是合法 UTF-8；允许开头出现 **UTF-8 BOM**（`EF BB BF`）。
- 根值必须是对象。
- 同一个 JSON 对象里出现重名成员，整份拒绝。
- 根值解析完之后还有非空白内容（两个 JSON 值拼接），整份拒绝。
- 嵌套深度按“根对象/数组算第 1 层”计数，超过 32 层拒绝。
- `label` / `value` 的“单行”指不含任一元硬换行：U+000A（LF）、U+000D（CR）、U+000B（VT）、
  U+000C（FF）、U+0085（NEL）、U+2028（LS）、U+2029（PS）；
  制表符（U+0009）与其它控制字符不在此列，不额外限制。
- “空白”指空串，或只由 Unicode White_Space 字符组成：
  U+0009..U+000D、U+0020、U+0085、U+00A0、U+1680、U+2000..U+200A、U+2028、U+2029、
  U+202F、U+205F、U+3000。

## 完整替换语义

- 每一份被接纳的快照是当前内容的**完整版本**，不是增量补丁。
- `items` 的数组顺序就是显示顺序；未出现的旧条目立即消失。
- 未过期的合法 `items: []` **立即清空内容**，这不是取数失败。
- 清空之后若网络或校验失败，没有可保留的条目，只能显示红色 `ERROR`；
  **不得**找回清空前的历史值。
- 切换到不同 URL 时清空旧源缓存；同一 URL 的重新绑定不要求清缓存。
- 快照与失效状态仅保存在内存，重启后不恢复上次读数。

## 失效、恢复与到期

- 取数或校验失败**一发生**就进入整体失效状态：
  - 有当前条目：保持其值，**立即把值全部染红**，并给出失败原因；
  - 没有条目：显示红色 `ERROR`，详情说明原因。
- 不设宽限期、不设保留截止时间、不在若干分钟后删除旧值。
- 收到合法且未过期的快照后，恢复**每一条生产端指定的 `state`**，不能一律恢复成正常色。
- `expiresAtMs` 是绝对到期时间：主进程按自己的定时器判定到期，不依赖下一次轮询响应。
- 同一份旧快照反复以 HTTP 200 返回，**不会**延长到期时间，也洗不掉过期状态。
- 过期与通信失败同属整体失效：有条目就保留值并染红，没有条目就红色 `ERROR`。
- **第一份**收到的快照即使结构合法、含条目但已经过期，也接纳其内容并全部染红。
- 不提供 `expiresAtMs` 时，只根据通信/校验健康状态判断，**不从快照的语义年龄推断失效**。

悬浮窗与任务栏读的是同一份快照与同一套规则，所以在结构上不可能出现“一面正常、一面失效”。

## 启动行为

- 新实例没有已保存的 URL：显示红色 `ERROR`，详情为“未配置 URL”；
  不使用任何默认地址，也不猜端口。
- 有 URL、首次请求还在等待：不显示读数，也不显示空窗；首次失败后才显示红色 `ERROR`。
- 隐藏悬浮窗不停止主进程、取数或任务栏组件。

## JSON Schema 表达不了的部分

`schema/snapshot-v1.schema.json` 覆盖字段类型、`state` 枚举、条目数与 `expiresAtMs` 的数值范围，
但下列内容只能靠检查器与说明：

- `id` 在快照内唯一；
- 字符串的 UTF-8 **字节**上限（Schema 的 `maxLength` 按码位计数，不是字节）；
- JSON 嵌套深度、BOM、重复成员等解析器层面的拒绝；
- 完整替换、失效/恢复、到期与启动状态机；
- HTTP 层规则（200 才接纳、重定向、超时预算）。

因此协议的正确性判据是 `deskfeed-check.exe` 与 `docs/testing.md` 里的用例，不是一个 Schema。
