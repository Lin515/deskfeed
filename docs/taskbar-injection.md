# 任务栏真嵌入与显示邮箱

> **离线侧已实现；真机侧尚未验收。** 显示邮箱（主进程发布“最新完整帧”）已经落地，并有一条按 scope
> 隔离的验收通道 `--frame-mailbox`；负载 `deskfeed-payload.dll`（生产）与
> `deskfeed-payload-test.dll`（同源自测）已经实现（只读最新显示帧、渲染进任务栏 XAML 树、收尾门禁
> 与进程守卫见 [native-safety.md](native-safety.md)），注入/卸载工具 `deskfeed-inject.exe` 与自测宿主
> `deskfeed-probe.exe` 也已经实现并有离线用例。
>
> **默认运行就会走这条路。** `[taskbar] component` 缺省为 `true`，主进程启动后会把任务栏编排武装成
> “开”，并按需调用 `deskfeed-inject.exe` 把负载装进当前任务栏属主进程——注入不是“需要额外打开”的
> 能力。只有 `--headless` / `--no-inject` / `--no-taskbar`（本次运行）或 `[taskbar] component=false`
> （持久）会让它一次动作都不发。真实注入必须由用户明确授权，并按
> [native-safety.md](native-safety.md) 的纪律逐轮做。
>
> **已验收 / 尚未验收**：真机 `explorer.exe` 注入与真机 XAML 走查、多屏块落点已在 2026-10-24 的
> 双屏环境完成（结论见 [testing.md](testing.md)）；帧生产/消费的 R5 目标修正、干净 checkout 上的
> Release 构建与部署仍未验收。检查点结论见
> [testing.md](testing.md)。本文记录设计、默认行为、硬性约束与已知风险。

## 目标

把主进程算出来的显示结果**真正嵌入** Windows 11 任务栏的 XAML 树（不是叠层、不是子窗口），
并在主进程退出或崩溃时把插入的元素与钩子清理干净，不遗留模块。

## 默认行为与开关

任务栏组件分成三件事，缺一个就会理解错：

- **持久意图**（`[taskbar] component`，缺省 `true`）：用户想不想要这个组件。
- **本次能力**：没关任务栏、显示邮箱建起来了、注入器真的在。它决定悬浮窗菜单项灰不灰。
- **当前生效** = 意图 ∧ 能力：菜单的勾、也是交给编排层的目标状态。

编排层（`src/master/taskbar_supervisor.*`）**不注入**：它只按有界的命令行契约异步调用
`deskfeed-inject.exe --load/--stop/--status`，同时只允许一个动作在跑，用零等待回收子进程，
**绝不阻塞等待、绝不强杀**；卸载的判据是注入器自己的退出码 0，非 0 一律视为“未撤下”。
主进程收尾时只请求一次停止，不等待、不重试。

- 关掉本次运行的任务栏动作：`--no-inject` / `--no-taskbar`；连悬浮窗一起关：`--headless`。
- 持久关掉：设置文件写 `[taskbar] component=false`（缺省是开）。
- 持久选择屏幕：设置文件写 `[taskbar] screens=...`，或从托盘读数块 / 悬浮窗的右键菜单勾选。
  键不存在时按“仅主屏”处理；`screens=` 空值表示明确不在任何任务栏显示。
- 没有显示邮箱就不武装编排层：一次注入动作都不会发，而不是“武装成关”。

## 多屏与退化

托盘读数可以同时显示在多块屏幕的任务栏上。每块屏幕对应一个任务栏窗口：主屏是 `Shell_TrayWnd`，
副屏是各自的 `Shell_SecondaryTrayWnd`。负载在注入时枚举全部任务栏窗口，并在一次注入里为每块
屏幕保留一个 XAML 托盘元素，之后运行期只增删块、换文字，不再重连诊断。

- **配置是“启用集合”**：菜单里的勾按持久配置画，不按本次退化后的实际落点画。勾选/取消走主进程
  的落盘事务，成功后主进程重发一帧显示配置，负载据此增删各屏的块。
- **退化规则**（完整规则与纯逻辑在 `src/display/taskbar_layout.*`）：
  - 配置了一块或多块屏幕，但**所有**被启用的屏幕当前都不可用（没有对应任务栏窗口，或托盘元素
    解析不出来），而主屏可用：只在主屏显示。**退化不写回配置**。
  - 配置本身为空（`screens=`）：不在任何任务栏显示，**不退化**。
  - 配置了多块而只有部分不可用：可用的那几块照常显示，**不退化**，也不额外加主屏。
  - 配置的主屏自己也不可用：没有可退化的目标，不显示；等任务栏恢复后由下一次注入重新判断。
- **可用性判据**是“当前有没有能落块的任务栏目标”，不是显示器的名称或分辨率。任务栏窗口消失
  （拔屏、任务栏重启、Windows 关闭“在所有显示器上显示任务栏”）都会让那块屏幕在运行期变为
  不可用；负载会在下一次读数/协调时重新计算退化。
- **运行期只处理“消失”**：新的任务栏窗口出现需要重新注入才能获取它的 XAML 元素（一次注入不
  重复走查）。拔掉屏幕后配置项仍在，重新接回**同一个显示器接口**时会自动恢复。
- **屏幕身份**用显示器接口路径（`\\?\DISPLAY#...`），不用 `\\.\DISPLAYn`：后者会随主屏切换、
  拔插和拓扑变化整体移位，会让配置指到另一块屏幕上。屏幕标签（`屏幕 1（主）`）只用于菜单显示，
  不写进配置。
- **任务栏线程**：所有任务栏窗口必须在同一条 shell UI 线程上（Windows 11 的实际形状）。模块的
  钩子静止证明是一条线程一份的；遇到跨线程的任务栏窗口会保守地跳过并记日志，而不是把“最后一条
  线程已退休”当成所有线程都退休。
- **元素解析在线程上**：走查在负载线程发起，句柄解析与屏幕归属判断都在任务栏线程上做（XAML
  元素有线程亲和性）。
- **屏幕归属靠几何锚点**：Windows 没有公开 API 把 `XamlRoot` 映射回承载它的 HWND——真机上任务栏
  元素的 UIA peer 全部为空、拿不到边界矩形，`DesktopWindowXamlSource` 也不从内容侧暴露窗口，
  XAML 焦点同样只能落到岛内、不会跟着换 Win32 输入宿主窗口。负载改为比较两侧的同一个位置：
  岛内首个可聚焦控件（任务栏“开始”按钮）的岛内偏移（DIP × `RasterizationScale`）与每块任务栏
  `Start` 子窗口相对任务栏左边的偏移。只有**唯一**命中才认账，探针本身只读（不移动焦点、不注入
  输入）。对不上或同时命中多块时，该岛保持未识别，只由“同一条线程上只剩一个未配对元素与一个
  未配对屏幕”的无歧义补齐兜底，否则那块屏幕不放块——绝不按走查顺序猜（真机上走查顺序与屏幕
  顺序不一致，曾把左右屏配反）。**已知边界**：两块及以上任务栏的锚点完全相同时无法区分，这些
  屏幕不会显示块，而不是猜一个。

## 硬性约束（每一条都是踩过的坑）

1. **真嵌入 XAML，不退回旧路线。** Windows 11 的任务栏由 XAML 层渲染，`SetParent` 的 GDI 子窗口
   在任务栏带内**完全不可见**；叠层置顶窗口会被任务栏自己盖住、还会压住任务栏按钮。两条都不要重试。
2. **按任务栏属主挑目标进程。** 目标是 `Shell_TrayWnd`（次选 `Shell_SecondaryTrayWnd`）的属主进程，
   不是进程列表里的第一个 `explorer.exe`：shell 崩溃重启后旧进程常赖着不走，只有属主那棵树里有
   托盘元素，装错进程会让读数永远不出现。卸载时顺手把别的 `explorer.exe` 里的残留负载也清掉。
3. **每个 XAML 核心最多走查一次。** 用公开的 XAML 诊断接口（`InitializeXamlDiagnosticsEx` +
   `IXamlDiagnostics` + `AdviseVisualTreeChange`，负载 DLL 自己充当 TAP）拿到元素后，
   **立刻关闭诊断连接**、还回走查句柄与站点引用；运行期只换已持有元素的文字与前景色。
   多屏时按核心逐个走查、每块托盘元素拿到就停止；反复走查会在任务栏线程上重建 composition
   走查器，是这条路线风险最高的操作。
4. **XAML 对象只在任务栏 UI 线程上碰。** 跨线程操作要经线程级 `WH_GETMESSAGE` 钩子进场并自摘，
   不在任务栏线程上留常驻改动。
5. **禁止替换 `Shell_TrayWnd` 的窗口过程**（实测约 10 秒后 explorer 崩溃重启）。
6. **拆除时不要调用 `DispatcherQueueController::ShutdownQueueAsync()`**：它的完成回调会回到本模块，
   实测直接把 explorer 打崩。
7. **模块引用按实际交出的站点数归还**（每个走查站点一次，不是每进程一次）；多核心宿主
   （explorer 有 3 个 XAML 核心应答端口）尤其要按实际交出的 site 计数。
8. **线程入口与危险探针同时处理 C++ 异常与 SEH**；SEH 小函数不混带析构对象；异常处理里记录
   异常码与出错地址（相对 `taskbar.dll` 与本模块），否则无法定位。
9. **悬停提示两侧一致**：最大宽度 420（`TTM_SETMAXTIPWIDTH`），`TOOLINFOW::cbSize` 按进程里
   实际生效的 comctl32 版本做候选重试，负载 DLL 的清单声明 comctl32 6.0 依赖。
10. **字体常规字重**，前缀与数值只用取色区分；读数块最多三行；字号按托盘给的高度自适应。
11. **测试宿主先行**：改这块代码先跑不起窗口/不注入 explorer 的自测宿主，再按
    “注入 → 观察 → 立刻 stop”的纪律做真机实验；每轮先确认上一轮的看门狗与后台进程已结束，
    日志在下一轮之前复制走（负载日志按写打开，每注入一次截断一次）。

## 显示邮箱（Windows 共享内存 + 通知事件）

- 主进程统一做 HTTP、解析、校验、缓存、到期与整体失效判断；悬浮窗由主进程渲染，
  并通过共享内存把**有大小上限的完整显示帧**发给任务栏 DLL。
- 邮箱语义是“最新显示帧”：**不排队积压历史帧**；DLL 重新加载时直接取当前最新帧。
- 帧格式 v2 在读数之前带一节**托盘屏幕配置**：是否显式配置 + 启用的屏幕标识表。它随配置变化
  重发，且不受快照 revision 影响；负载据此决定哪些任务栏上要有块。
- 帧头必须带版本、总长、代次与**主进程归属信息**（版本 + 拥有者 + 主进程 PID）；
  读取方要用一个**活的进程句柄**核对主进程 PID 与创建时间，防止 PID 复用后读到陌生进程的帧。
- 提交必须是完整的：先写好帧体，再在同步下写帧头/置代次，最后置通知事件；
  读取方校验长度、版本与完整性，绝不无界读取共享内存。
- DLL 仍然要做长度、完整性与版本检查：“主进程已校验 HTTP”不等于 DLL 可以无界读取。
- 通知与读写同步不得丢失最后一次更新；主进程正常退出或崩溃时 DLL 要能唤醒并清理任务栏组件，
  不遗留旧读数。
- DLL 只展示主进程结果：**不做外部 HTTP、不解释业务语义、不自己判断健康/到期**。
- 显示通道与命令控制通道分离；生产端不需要了解任何内部线格式。

## 命名（公开侧）

- 负载 DLL：`deskfeed-payload.dll`
- 共享内存：`Local\DeskFeed-display-frame`；通知事件：`Local\DeskFeed-display-ready`
- 负载清理事件：`Local\DeskFeed-payload-cleanup-<pid>`
- 负载导出（生产）：`DeskFeedStart` / `DeskFeedStop` / `DeskFeedGetStatus`，外加两个 COM 入口
  `DllGetClassObject` / `DllCanUnloadNow`；`DeskFeedProbe*` / `DeskFeedTest*` 只在自测与测试构建里存在
- 注入工具：`deskfeed-inject.exe`；自测宿主：`deskfeed-probe.exe`
- 互斥体与控制窗口类名都带当前用户 SID 的短哈希（与主进程的做法一致）

## 已知风险

- 负载运行在 `explorer.exe` 内，任何未捕获的异常或访问违例都会连带结束桌面与任务栏
  （explorer 会自动重启，但用户正在做的事会中断）。
- 历史上有一例 explorer 在 `Windows.UI.Xaml.dll` 里崩溃，当时负载并不在那个进程里：
  **既不能归因于本负载，也不能排除**。不能宣称注入绝对安全。
- 注入使用 `CreateRemoteThread` + `LoadLibraryW`，属于会被安全软件关注的行为。

## 桌面悬浮窗（第三个阶段）

- 位置以窗口**右下角**为锚（`[window] right` / `bottom`），尺寸变化时保持这个角不动。
- 全屏让位只认 `rcMonitor` 与 `SHQueryUserNotificationState()`，不认“任务栏可见高度”；
  任何一步读不到都按“不是全屏”处理，宁可显示也不把用户该看见的窗口藏没了。
- 置顶是窗口的系统状态：需要每秒一次的守护，只在“该置顶而样式里没有这一位，或被别的进程的
  可见窗口压住（命中测试优先）”时才补一次；不无条件重抬。
- 详细/隐藏/任务栏组件/置顶这些可切换状态一律**在切换的那一刻整体落盘**，不等到退出。
- 悬浮窗右键菜单还有「托盘屏幕」子菜单：每次弹出前现查任务栏窗口与持久配置，按屏幕给出勾选；
  勾选/取消由主进程落盘并重发显示帧。配置成“不在任何任务栏显示”时托盘上已经没有块可右键，
  这个子菜单就是重新打开的入口。
- 隐藏悬浮窗不停止主进程、取数或任务栏组件。
