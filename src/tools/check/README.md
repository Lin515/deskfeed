# src/tools/check

`deskfeed-check`（离线协议检查器与 HTTP 量具）的全部实现。它回答一个问题：
“主进程会不会接纳这份快照正文”。

| 文件 | 作用 |
| --- | --- |
| `main.cpp` | 参数解析、正文来源（`--file` / `--stdin` / `--url`）、报告输出与退出码。 |

## 行为要点

- 不建互斥体、不开窗口、不注入任何进程；`--url` 走的正是主进程那份 `http_get` 与
  `snapshot_validate`，所以“主进程会接纳什么”可以用一条命令问清楚。
- 退出码固定：`0` 接受、`2` 拒绝（HTTP 或校验）、`1` 用法或内部错误。
- `--report json` 打印**一行合法 JSON**，接受与拒绝两条路径都是，可以直接交给任何严格
  解析器。机器可读输出不能只在其中一条路径上成立。
- `--stdin` 按**字节流**读取，管道与文件重定向都支持：管道写端关闭时的
  `ERROR_BROKEN_PIPE` 是正常的流结束，不是读取失败。程序化调用者（起子进程喂管道）与
  shell 的 `< file` 同样可用。

用法与退出码的权威说明见 [docs/testing.md](../../../docs/testing.md)。
