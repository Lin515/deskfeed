# src/widget

桌面悬浮窗（Phase 3）。它是主进程里**一个窗口**，消费主进程已经算好的显示帧；取数与状态判断
一律不在这里。

## 责任边界

窗口只做四件事：把帧画出来、按内容定尺寸、按右下角锚点落位、把用户的四个动作交回主进程。

它**不做**这些（都由主进程 `src/master/` 负责）：

- 不联网、不解析 JSON、不校验快照、不缓存、不判断到期与整体失效；
- 不绑定生产者进程、不碰单实例仲裁、不碰控制通道与显示邮箱；
- 不持有 `SettingsFile`：界面偏好由主进程那一份设置文件落盘（见下）；
- 没有自己的守护线程，也不碰任务栏注入——任务栏组件开关只是交给主进程的一个意图。

窗口的 HWND 建在主进程现有线程上，主进程那条 `MsgWaitForMultipleObjects` + `PeekMessage`
循环已经会泵它的消息，所以这里不需要新的线程或消息循环。

## 文件

| 文件 | 作用 |
| --- | --- |
| `window.h` / `window.cpp` | 窗口本体：建窗、换内容、定尺寸、落位、绘制、悬停提示、右键菜单、拖动与双击展开、置顶守护、全屏让位。`window.h` 是主进程依赖的稳定接口（实现细节走 pimpl）。 |
| `preferences.h` / `preferences.cpp` | settings.ini 的 `[window]` 一节 ↔ `WindowPreferences`。只借用主进程那份 `SettingsFile`，不持有、不重新读盘。 |
| `theme.h` / `theme.cpp` | 配色与字体。**整窗没有粗体**：前缀与读数只用取色区分（弱色 / 主色），读数另有一档警告色。 |
| `text_metrics.h` / `text_metrics.cpp` | 紧文字测量（前缀后不多留空格）与详情换行。量法与画法必须同源。 |
| `fullscreen.h` / `fullscreen.cpp` | 前台是否全屏。只认显示器 `rcMonitor` 与 `SHQueryUserNotificationState`，判不出来一律“不是全屏”。 |

显示排版本身不在这里，而在 [`src/display/reading.h`](../display/reading.h)：桌面悬浮窗、任务栏
读数块与离线量具共用同一份折行与文本口径。

## 显示规则

- 一行 = `label + " " + value`（label 为空时只写 value）；折行后同一视觉行的条目用 `" · "` 连接。
- 折行：3 个及以下一行一个；4 个及以上每行 `ceil(rows / 3)` 个，**最多 3 行**。
  ≤5 条时与旧原生实现逐字一致（4 个 → 2 行，5 个 → 2+2+1 三行）。
- **>5 条的通用有界分组**：一条视觉行最多画 4 个条目，多出来的收成行尾一个 `…（另有 N 项）`
  标记；标记的悬停文本逐条列出被折掉的 `label value`（非正常状态带 `（警告）`/`（错误）`），
  标记本身的颜色取被折掉那些条目里最重的一档（有错误就红、否则有警告就琥珀），所以折掉的
  里面有 error/warn 时在行上就看得出来；展开详情也逐条列出**每一个**条目的 `label value`。
  有界分组只是不画在行上，不是把内容丢掉。
  64 条（协议上限）按公式是每行 22 个，若不设上限，一行会横向长到屏幕外；上限只在这个区间
  生效，≤5 条永远碰不到。
- **展开详情逐条列出每一个条目**：标题是该条目的行文本 `label + " " + value`，条目自己的
  `detail` 非空时再缩进在其下。这里刻意不以“有没有 detail”决定要不要出现——`value` 是条目
  唯一的主读数，协议允许省略 `detail`；只列 detail 非空的条目，会让有界分组折掉的那些 value
  再也看不到。也不要求生产端把 value 重复写进 detail。
- **逐字一致的范围要说清**：只有「`ViewKind::Content`、`alarm` 为假、≤5 条」时的**可见行**与
  **悬停文本**与旧原生实现逐字相同（旧基线里 DS/CC 那两条补充说明是主控批准的额外信息，
  不计在内）。下面这些都是刻意的 v1 差异，不是回归；也不要对外宣称整个界面与旧实现
  逐像素或逐字节相同：
  * 展开详情是通用重新排版：它一定带上每个条目的 value，与旧实现的展开块不同；
  * 没有可显示的值时写红色 `ERROR`（旧实现写「取数失败」）；
  * `alarm`（有值但整体失效）在 v1 里没有“沿用上一次读数”的宽限期，状态行写「整体失效」，
    量具头部追加 `alarm=yes`；旧实现是 stale / 保留窗口那一套。
- 颜色三档：`state: "ok"` 正常、`state: "warn"` 警告色、`state: "error"` 错误色。生产端的
  `warn` 有自己的一档，既不会被折成正常色，也不会被折成错误色。
- 整体失效（帧的 `alarm`）：保留各条目的值并整行标红，悬停文本是**失效原因在前、生产端 detail
  在后**——原因看得见，生产端原本写的那点上下文也不会被顶掉。`alarm` 与 `failure`（没有值、
  只有一行 `ERROR`）是两条独立信息：有值时的整体失效**不**被折成 failure，值一个都不丢；
  展开详情里失效原因只在**顶层说一次**，不在每个条目下面重复。
- 没有可显示的值时：一行红色 `ERROR`，原因写进悬停与展开详情（含“未配置 URL”）。
- 等待首份快照（`ViewKind::Waiting`）：一行都不显示，窗口不出现（不露空窗）；合法的空条目
  则整窗隐藏，这不是错误。

## 不倒退的稳定性约束

- **落位基准是窗口右下角**（`[window]` 记 `right`/`bottom`）：尺寸变化时保持这个角不动、向左上
  生长；判断“在哪块屏”用**左上角**（贴屏时锚点正好落在两块屏交界上）。
- **紧文字、常规字重**：前缀与读数之间只有一个空格，前缀与读数用同一字族、同一字号、同一字重，
  只靠取色区分。悬停提示与任务栏那侧同宽：`TTM_SETMAXTIPWIDTH` 用 **420**，并且进程要带
  comctl32 **v6** 清单；`TTM_ADDTOOL` 的 `cbSize` 按候选试（v6 认 `sizeof(TOOLINFOW)`），
  别写死一个值。
- **全屏让位只认 `rcMonitor`**，不认“任务栏可见高度”；判定任何一步失败都当“不是全屏”
  （宁可显示，也不许把用户该看见的窗口藏没了）。全屏期间跳过置顶守护。
- **置顶是条件守护，不是每秒重抬**：只在“该置顶而样式里没有这一位，或被别的进程的可见窗口
  压住”时补一次；判据顺序是 `covered_by_foreign_window(&detail) || overlapped_from_above()`，
  **命中测试必须写在 `||` 前面**（写反了短路会吃掉命中测试，日志里的 `cover=` 永远是空的）；
  “被压住”的日志按 10 秒节流，恢复正常后立刻又能记。
- **可切换状态在切换的那一刻落盘**：详细/精简、隐藏/显示、置顶、窗口位置都在同一个动作里
  整体写一次 `[window]`，不等退出。落盘失败则**回滚内存里的值**，让界面与磁盘一致。
- **隐藏不停主进程**：`hidden` 只压住窗口的显示，取数、任务栏组件与主进程照旧运行；
  `--hidden` 是本次运行的强制隐藏，**不落盘**。
- 拖动与双击按窗口消息自己判定（把鼠标消息换算成屏幕坐标），不依赖现成控件的双击事件。

## 偏好落盘为什么必须走主进程

`SettingsFile` 在内存里是一份“打开时的原文 + 改动”，`save()` 把整份重新渲染出去。如果窗口自己
再打开一份，它渲染的是**打开那一刻**的旧快照：用户刚用 `--url` 换了源，窗口紧接着切一次置顶，
旧快照就会把新地址覆盖回去。

所以窗口不持有 `SettingsFile`：主进程把偏好传进来，窗口通过 `save_preferences` 回调让主进程在
**同一份**对象上改 `[window]` 并保存。两边都在主进程那一个线程上跑，不存在并发交错。

`write_window_preferences` **会改传进去的那个对象**（`set` 改内存里的行；保存失败时它还会
`load` 一次，把脏改动丢回磁盘状态）。所以主进程要按 “clone → 改 → 保存 → 成功才 adopt” 来用：
在一份**候选副本**上调用它（`SettingsFile candidate = *settings_;`，这个类可拷贝），只有返回
true 才把候选换成当前使用的实例。直接对正在用的实例调用，一旦保存失败、连重新 `load` 也失败，
内存里的 URL / 调度就可能与磁盘不一致。

## 开发期验证（不进版本库）

`.agent/widget/` 里有一个隔离的 CMake 工程，只编 `src/display/reading.*` 与它需要的 core 源文件：

```powershell
# 先 chcp 65001，再 call vcvarsall.bat x64，同一条 cmd 里：
cmake -S .agent/widget -B .agent/build/widget -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build .agent/build/widget
ctest --test-dir .agent/build/widget --output-on-failure
```

产物里有两个 exe：`deskfeed-reading-tests.exe`（纯排版用例）与 `deskfeed-reading-gauge.exe`
（离线显示量具：`--reading-rows <通用v1快照.json>` / `--reading <...>`）。量具只认通用 v1 协议，
读不懂就退出 1；它让“≤5 条与冻结基线逐字一致”在悬浮窗落地之前就能验。
